### Polar converter, native (2026-10-27)
`native/src/polar_convert.{hpp,cpp}` + `polar_main.cpp` = C++ port of `python/gcode_to_polar.py` (executable `apex_gcode_to_polar`, built by `node native/build.cjs` with the rest; Electron prefers it, `electron/python-runner.cjs` falls back to the Python script when it is absent). **Byte-identical output** to the script on a 285 950-move G-code in both modes (`scripts/check_polar_parity.py <gcode> <exe>`), 7.0 s → 2.2 s (4 cores) and independent of the thread count (no float reduction is split between threads): height map per layer, normal per move, subdivision count per segment and text formatting run in parallel; the unwrapped angle / E / feed chain stays sequential (segments through the plate axis are resolved in that pass, their subdivision depends on the real angle).
- **Dynamic mode, changed behaviour (user's remark: the converter produced collisions)**: B is bounded to `[--b-min (0), --b-limit]` — the machine only tilts toward +R, B ≥ 0 (the old ±limit gave B down to −27° in the uploaded file). The Python script has the same `--b-min`.
- **Collision avoidance** (native only, needs `--head-samples native/data/head-samples.bin`, float32 x,y,z in the head frame; regenerate with `node scripts/gen-head-samples.cjs`, same algorithm as `getHeadSamples`): same rule as the Édition panel (engine step-9 `PastMaterialIndex`; nozzle zone ≤ 10 mm tolerates 0.18 mm, rest of head 0.7 mm; plate keeps 1 mm; samples within 3 mm of the tip ignored; one pose tested every 1 mm of bead). Flagged poses are re-solved by a **dynamic programme over B** in a window around them (B grid = rate × spacing, transitions limited by the B rate 2°/mm, cost = distance to the normal-derived B, states collision-free), poses are independent (matter depends on positions only) so windows run in parallel. Summary reports `collisionsBefore/After`, `posesTested`, `reorientedMoves`, `maxTipRadiusMm`, `beyondPlateMoves` (shown in the toast).
- Measured on the uploaded `test_non_planaire` file: 0 collisions on 123 002 poses with B ≥ 0 and the tolerances above (3 grazing contacts and 262 at margin 0 with the old negative B). Stress (body tolerance −3.5, reach 3.7 mm): 133 → 129 remaining, 195 → 28 when the rate limit is lifted: the rest is infeasible within the B rate, reported as unresolved, never hidden. Not checked: in-between points (only poses), travel moves, the pivot radius vs the machine's X travel (reported only), real printing.
